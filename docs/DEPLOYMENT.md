# 🚀 DEPLOYMENT · JAIVARDHAN OS

> How this README ships, regenerates, and stays alive.

## Prerequisites

- A GitHub account (you have one).
- The `jv-singh/jv-singh` repo (already exists).
- Optional but recommended:
  - `METRICS_TOKEN` (a PAT with `repo` + `read:user`) — for the lowlighter/metrics action.
  - The repo set as your GitHub **profile README** (this repo must be your username).

## 1 · Enable Profile README

On GitHub: visit `github.com/jv-singh/jv-singh` → **Settings** → check
**"Include this repository in your profile"** in the "Features" section
(it's actually a single button on the home repo page if name = username).

GitHub will then render `README.md` at the top of your profile.

## 2 · Secrets (optional)

For the metrics workflow to fetch private data:

1. Generate a PAT: `gh token create --scopes "repo,read:user,read:org"`
2. In repo **Settings → Secrets and variables → Actions**, add:
   - `METRICS_TOKEN` — the PAT above
   - `GITHUB_TOKEN` — provided automatically by GitHub
3. The `metrics.yml` and `snake.yml` workflows will start producing output.

## 3 · Workflows in `.github/workflows/`

| workflow | schedule | what it does |
|---|---|---|
| `metrics.yml` | hourly | generates metrics SVG into `output` branch |
| `snake.yml` | daily | generates contribution snake into `output` branch |
| `auto-update.yml` | daily | bumps `LAST_BUILD_DATE` in README |
| `lint-assets.yml` | on PR | SVGO-lints SVGs in `assets/svg/` |

The output of metrics/snake goes to the `output` branch via `crazy-max/ghaction-github-pages`,
which GitHub Pages then serves at `jv-singh.github.io/jv-singh/...`.

## 4 · Regenerate live assets

Three SVGs are generated by Python scripts in `scripts/python/`:

```bash
PYTHONIOENCODING=utf-8 python scripts/python/generate_assets.py
```

This writes:

- `assets/svg/sections/status.svg` — live process status
- `assets/svg/sections/heatmap.svg` — 52-week heatmap
- `assets/svg/sections/skill-tree.svg` — animated skill tree

You can call them individually:

```bash
python scripts/python/generate_status.py > assets/svg/sections/status.svg
```

To auto-regenerate on every commit, add this job to a workflow:

```yaml
- name: Generate live SVGs
  run: |
    PYTHONIOENCODING=utf-8 python scripts/python/generate_assets.py
```

## 5 · Add a new project

1. Save the poster SVG into `assets/svg/projects/your-project.svg` (use the existing posters as templates).
2. Add a new section block in `README.md`:

```markdown
## <img src="./assets/svg/icons/your-icon.svg" width="32"/> 27 · NEW SHIP

<div align="center">
<img src="./assets/svg/projects/your-project.svg" width="100%" alt="Your Project"/>
</div>

| domain | stack | impact |
|:---|:---|:---|
| ... | ... | ... |
```

3. Renumber subsequent sections.

## 6 · Add a new meter / radar / galaxy

Drop a new SVG into `assets/svg/meters/`. Match the existing pattern:

- Title strip: `▸ NAME · STATUS`
- Caption strip: top-right or bottom-right
- Outer panel `rx=6`, stroke `#1e1b4b`
- Color usage from the shared palette

Then reference it from a new section in `README.md`.

## 7 · Pin the repo (optional)

Visit `github.com/jv-singh` → **Customize your pins** → pin `jv-singh/jv-singh`.
The repo itself becomes the "pinned project."

- ✅ Hero HUD with name + telemetry

- ✅ AI Consciousness meter
- ✅ Brain waves animating
- ✅ Innovation radar sweeping
- ✅ Skill galaxy orbiting
- ✅ 5 cinematic project posters
- ✅ Snake animation at section 20
- ✅ Live GitHub stats

If any panel looks blank, check the SVG file in DevTools — GitHub sometimes
rate-limits images that contain `<script>` (none of ours do).

## 9 · Maintenance

- **Daily:** `auto-update.yml` stamps the date.
- **Hourly:** `metrics.yml` refreshes GitHub metrics.
- **Daily:** `snake.yml` refreshes the contribution snake.
- **Per release:** regenerate the live SVGs and add a new project poster.
